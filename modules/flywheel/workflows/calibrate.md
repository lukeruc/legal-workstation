# 校准分析工作流

`/flywheel` 触发时执行本工作流。

## Step 1: 读取数据

### 1.1 读索引

读 `records/INDEX.md`。提取全量记录列表——日期、ID、类型、合同名、当事方、风险评级。

如果 INDEX.md 不存在或仅有表头，报告"尚无工作记录，无法执行校准分析"并终止。

### 1.2 读统计

```bash
ls records/_stats/*.json 2>/dev/null
```

逐个读取，获取按类型聚合的统计数据。

### 1.3 评估数据质量

从 INDEX 中统计：
- 总记录数
- 各类型记录数
- 时间跨度（最早—最晚日期）

抽样 2-3 条 `records/{date}-{slug}.md`，检查 frontmatter 中是否存在 clause、risk_distribution、mode 等字段，判断记录贫富程度。

### 1.4 按需深度采样

对满足最低阈值的合同类型，读取最近 5-10 条富记录（如有）的完整 frontmatter 和正文摘要。不读全文——frontmatter 和首段摘要已足够分析。

---

## Step 2: 读取参考系

```bash
ls playbook/contracts/review/*.md 2>/dev/null
```

读取 `.claude/profiles/` 下全部 `.md` 文件。

读取 `records/_stats/_regime.md`（如存在）获取当前格局标签。

---

## Step 3: 执行分析

三个维度独立运行。维度不达最低数据量要求时跳过。

### 3.1 规则偏差

**最低数据量**：至少一个合同类型有 ≥ 3 条记录。

**规则空白检测**：
- 从 INDEX 提取所有出现的 type 值
- 与 `playbook/contracts/review/` 下文件名对比（不含扩展名）
- INDEX 中出现但 review/ 下无对应文件的 → 规则空白
- 同类型 ≥ 3 条记录时予报告

**闲置规则检测**：
- `playbook/contracts/review/` 下有文件但 INDEX 中从未出现对应类型
- 总记录 ≥ 10 时予报告

**条款风险集中度**（需富记录）：
- 对同类型合同的富记录，统计各 clause 的风险分布
- 某条款维度持续出现中高风险但当前审查规则中未列为重点 → 报告
- 同类型富记录 ≥ 5 条时执行

**谈判模式**（需富记录）：
- 统计同一 clause rule 的 result 字段
- 持续 "negotiated" → 原模板立场可能需要调整
- 持续 "accepted" → 该条款可能不需要重点审查
- 同类型富记录 ≥ 5 条时执行

### 3.2 档案偏差

**最低数据量**：总记录 ≥ 10。

**合同类型偏移**：
- 统计 INDEX 中各 type 的占比
- 某类型占比 > 40% 但档案中未提及 → 报告

**立场一致性**：
- 统计各 stance 的占比
- 某立场占比 > 80% 但档案"常用交易角色"未体现 → 报告

**风险偏好偏差**（需富记录）：
- 从富记录的 clause result 推算实际接受度
- 档案声明"保守"但大量高风险条款被接受 → 报告
- 同类型富记录 ≥ 5 条时执行

### 3.3 格局检测

**最低数据量**：至少一个合同类型有 ≥ 10 条记录。

同一合同类型的记录按时间排列，检查风险分布是否出现显著偏移：
- 将记录按时序分为前后两段
- 比较两段的高/中/低风险比例
- 如果高风险占比变化 ≥ 15pp 且持续 ≥ 5 条记录 → 建议标记格局断点

格局标签由用户确认后手动写入 `records/_stats/_regime.md`。飞轮不自动标记。

---

## Step 4: 呈现报告

在对话中输出，格式如下：

```
## 统计概览
总记录 {N} 条（{最早日期} 至 {最晚日期}）
按类型：{type1} {n1}, {type2} {n2}...
风险：高 {H} 中 {M} 低 {L} 未评级 {U}
当前格局：{格局名}（如有）

## 规则偏差
[每条：发现 + 证据 + 建议行动（指向 /rule-builder）]
[无发现时：未检测到明显偏差。]

## 档案偏差
[每条：发现 + 证据 + 建议行动（指向 profile update）]
[无发现时：未检测到明显偏差。]

## 格局
[有断点信号时：建议标记新格局 + 理由]
[无断点信号时：当前格局无明显变化。]
[数据不足以分析格局时：跳过，说明原因。]
```

**每条发现必须附带**：
- 具体数字作为证据（如"5 份中 4 份"而非"多份"）
- 建议的后续行动（指向 `/rule-builder`、profile update、手动编辑 `_regime.md`）
- 数据不足以支持时明确说明"当前数据量较少，建议积累更多记录后重新运行 /flywheel"

**报告完成后结束**——不等待用户"采纳"或"拒绝"。用户听完自行决定是否行动。
